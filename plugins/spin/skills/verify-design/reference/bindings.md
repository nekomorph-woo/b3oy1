# Binding specimens

Worked verification chains per archetype. Each specimen: the task, the chain as designed, and what the audit caught. Lab specimens come from the nested-session practice that produced this skill (flowlab); industry specimens were collected and verified against primary sources.

## bugfix

**Industry:** Django's patch policy makes the regression test half of the fix itself, and its review checklist judges the test by a two-state flip — "Is there a proper regression test (the test should fail before the fix is applied)?" (docs.djangoproject.com/en/dev/internals/contributing/writing-code/submitting-patches/). Rails institutionalizes the same anchor at the issue layer: bug reports ship an executable test case — "Having a way to reproduce your issue will help people confirm, investigate, and ultimately fix your issue. You can do this by providing an executable test case." (edgeguides.rubyonrails.org/contributing_to_ruby_on_rails.html). Both are the anchor-first principle at industry scale: the repro precedes and outranks the fix.

- **flowlab `add` ENOENT crash (lab P1).** Anchor: the observed crash (`node src/cli.js add` → ENOENT at store.js:6). Chain: repro command first (red-capable, deterministic, seconds), minimal fix, rerun of the original repro, neighbor check (`list` / `stats` untouched), cleanup of test artifacts before commit. What the audit caught: the executor's own pipeline measurement was lying (`head` ate the exit code) — the chain's rerun set surfaced it. Lesson: the rerun set exists for the auditor's tools, not the executor's confidence.

## feature

**Industry:** Gherkin's `Rule` keyword binds the rule/scenario layers natively — "A Rule is used to group together several scenarios that belong to this business rule", and the reference equates rule lists with "a list of business rules (general acceptance criteria)" (cucumber.io/docs/gherkin/reference). React's RFC process shows the rules-heavy shape: RFC 0188 states capabilities as ❌/✅ May/May-not rules, and attaches the enforcement ladder to the rules — "React will provide clear lint, build, and runtime errors for any violations." (github.com/reactjs/rfcs). Rules are the frozen layer; scenarios illustrate them; tooling is the command rung.

- **flowlab `top [N]` word-frequency command (lab P2).** Anchor: business rules agreed in a grilling pass — ten ambiguity dimensions each resolved against code facts (the existing n=1 tally in `stats.js` was the deciding anchor). Chain: 11 items, each a standalone command; family quotas present — adversarial entries on invalid N (`abc`/`0`/`-3`/`1.5` → non-zero), a side-effect lock (`cmp` byte-compare proving `top` reads without writing), a consistency anchor (`stats` output frozen verbatim so the new module could not drift the old tally). What the audit caught: the spec also flagged the README's `npm test` as a false claim and refused it as an acceptance vehicle. 11/11 passed independent rerun. Lesson: anchor quality is decided in the interview, not at chain time.

## delegated feature

- **flowlab `done <id>` command (lab P3).** Chain authored by the main session as a frozen JSON checklist (five criteria, commands embedded); executor allowed only to flip `passes` and add a `note`. Audit: character-level freeze check + full independent rerun + honesty comparison (executor flips vs physical results, 5/5). Lesson: the freeze converts honesty from a virtue into an auditable object — but with one specimen, it proves auditability, not model virtue.

## refactor / legacy

- **flowlab tally merge (lab R2).** Task: merge the duplicated tally loops in `stats.js` / `top.js` into one `src/tally.js`, byte-identical behavior. Chain: 12 items, golden master as the oracle (fixtures frozen by hash, master captured by a harness script, `diff -r master after` as the main verdict). What the design pass caught **before any code moved**: the two "duplicated" loops were not semantically identical — `stats` breaks ties by insertion order, `top` by alphabetical sort — so the chain carried an explicit item asserting the shared module contains no `sort()` (tie logic stays at the call sites). The designer's own golden-master experiments also produced the discipline's thesis: expectations come from running the pre-transform code, never from hand-derivation (its hand-computed tally was wrong; the master was right). What the audit caught: the chain's own R3 command used dialect-fragile grep (`\s` under ugrep), and its R1 baseline pin (`HEAD == <sha>`) went red after the refactor commit landed — both fixed as auditor change entries, the pin rewritten in ancestry form. Lesson: in a refactor chain, the interesting items are the *semantic differences hidden inside "duplicated" code*; and the auditor's tooling gets the same discipline as the executor — one premature verdict note, one pipeline-eaten exit code, and one heredoc-escaping mismatch were all caught by insisting on scripted amendments with immediate reruns.

## survey / legacy

- **flowlab-legacy structure map (lab P4).** Anchor: `file:line` evidence per claim, flags for the unverified (`?`) and contradictions (`!`) — 9 verified, 2 honestly open. The surveyor declined to exercise the `--csv` path (it would write into the repo, breaking the read-only discipline of a survey). What the audit caught: 6/6 spot-checked citations accurate; four latent bugs found by mapping alone (null-row crash, flag-order ENOENT, in-place mutation of caller data, verbose log polluting stdout). Lesson: a survey chain's quota is the flag — an unverified claim survives the audit only when flagged.

## decision / core domain

**Industry:** the mechanical rung for architecture decisions is the fitness function / dependency-rule family. ArchUnit turns "layer direction" into plain unit tests — "ArchUnit can check dependencies between packages and classes, layers and slices, check for cyclic dependencies and more… using any plain Java unit test framework" (archunit.org, quote verified) — and MADR gives decisions a durable, linkable clause form (adr.github.io/madr).

- **flowlab persistence single-point decision (lab R3).** Task: ratify "all command persistence goes through `src/store.js`; the command layer does no direct fs I/O" — mostly an acknowledgment of current shape, binding the future. Chain: 13 items = 11 command + 2 human, exactly the decision row's ladder theory (mechanical rung for structural properties — `grep -rnF` proved `fs` requires appear exactly once, in store.js:1; human rung routed the contract clause's meaning). The designer self-verified every anchor against code before emitting, and ran the mechanical group 8/8 as a design-phase self-check. Lesson: for ratifying decisions, the chain's job is proving the present already conforms, then freezing the rule so future drift is a red, not a debate.

## agent behavior

**Industry:** SWE-bench judges "fixed" as instance-level test reproduction — Verified is "a human-filtered subset of 500 instances", each scored by `% Resolved` against fail-to-pass / pass-to-pass test sets drawn from real GitHub issues (swebench.com). promptfoo's assertion catalog shows the ladder as a concrete API: ~30 deterministic types (`equals`/`contains`/`regex`/`is-json`/`javascript`/`python`/`levenshtein`/`latency`/`trajectory:tool-sequence`…, every type negatable with `not-`) versus ~15 model-assisted types (`llm-rubric`, `factuality`, `g-eval`, `select-best`) — the sandboxed judge is a listed rung, never the only one (promptfoo.dev/docs/configuration/expected-outputs).

- **verify-design judging itself (lab R4, self-hosting).** Task: design a chain that judges chain documents. The eval set was the three real chains the lab had already human-audited; the designer froze their hashes as the baseline, built the 14 judgments as prototype scripts calibrated outside the repo, **caught its own false positive** (an arrow function mistaken for a redirect; lookbehind fix with "missing beats false-positive" declared as an open question), then **mutation-tested its own teeth** — a negative matrix of defective chains, 11/11 bitten, before assembling the frozen JSON by script generation (zero hand-written escaping). Acceptance extracted commands literally from the JSON: 47/47; the auditor's independent rerun added a fourth chain (the meta-chain itself) for 56/56 greens with zero false bites, and two mutated negatives each bitten by exactly the judgment guarding that property. Lesson: in the agent-behavior archetype, the adversarial quota grows into a full negative matrix — a judgment that cannot go red on its defect is decoration, and error-analysis during design (the loop this archetype names) is where the false positives die.
